1  Adquisición de Datos y Configuración del Entorno

NoteCobertura del Módulo

Este capítulo cubre las Sesiones 1, 2 y 3 (Semana 1) de la materia. Está diseñado para sentar las bases conceptuales, metodológicas y de entorno necesarias antes de proceder a la manipulación de datos.

Este capítulo inicial sienta las bases técnicas y metodológicas necesarias para afrontar con éxito el ciclo de vida del análisis de datos. En primer lugar, abordaremos la configuración de un entorno de trabajo reproducible basado en proyectos y buenas prácticas de organización. Posteriormente, estudiaremos la fundamentación estadística de los datos antes de proceder a la ingesta práctica de archivos planos, hojas de cálculo, APIs y Web Scraping.

1.1 Configuración del Entorno y Flujo de Trabajo Basado en Proyectos

Para garantizar la reproducibilidad de nuestras investigaciones, utilizaremos de manera obligatoria el ecosistema conformado por R, el entorno de desarrollo integrado RStudio y el sistema de control de versiones Git/GitHub.

En el análisis de datos profesional, el uso de rutas absolutas rígidas (como C:/Usuarios/MiNombre/Documentos/datos.csv) o el empleo manual de setwd() son considerados malas prácticas que rompen la reproducibilidad Stoudt et al. (2021).

Para solucionar esto, RStudio introduce los Proyectos de RStudio (archivos con extensión .Rproj). Al abrir un proyecto, RStudio establece automáticamente el directorio de trabajo activo en la carpeta donde reside el archivo .Rproj. Esto permite gestionar todo el código mediante rutas relativas (por ejemplo, "data/registros.csv"), garantizando que el proyecto funcione de forma idéntica en cualquier otra computadora.

1.1.1 Estructura de Carpetas Recomendada

Todo proyecto analítico ordenado debe seguir una jerarquía estricta de subdirectorios dentro del directorio raíz Stoudt et al. (2021):

mi-proyecto/
├── mi-proyecto.Rproj  <- Archivo de proyecto de RStudio
├── data/              <- Carpeta contenedora de datos
│   ├── raw/           <- Datos originales (¡NUNCA SE MODIFICAN!)
│   └── processed/     <- Datos limpios listos para análisis
├── scripts/           <- Scripts de código R (.R) o documentos Quarto (.qmd)
├── figuras/           <- Gráficos y visualizaciones exportadas
└── docs/              <- Reportes, presentaciones y documentación adicional

1.1.2 Buenas Prácticas de Nomenclatura

Para evitar conflictos de codificación en distintos sistemas operativos y facilitar la legibilidad del código, se establecen las siguientes directrices de nomenclatura para archivos, scripts y variables:

  • Minúsculas siempre: Utilizar siempre letras minúsculas (evitar DatosRegistros.csv, preferir datos_registros.csv).
  • Sin espacios ni caracteres especiales: Reemplazar espacios por guiones medios (-) o bajos (_). Nunca usar tildes, la letra “ñ” o caracteres especiales en nombres de archivos o variables.
  • Nombres autodescriptivos pero cortos: El nombre debe indicar claramente el contenido (ej. 01_limpieza_ingresos.R).
  • Secuenciación de scripts: Si el análisis requiere varios pasos, anteponer números secuenciales para indicar el orden de ejecución (ej. 01_ingesta.R, 02_limpieza.R, 03_eda.R).
NoteActividad de Paso: Creación de la Estructura de un Proyecto (3 minutos)
  1. Abre RStudio. Ve a File > New Project…
  2. Selecciona New Directory > New Project. Nombra tu proyecto en minúsculas y sin espacios (ej. analisis-datos-bolivia).
  3. En la pestaña Files (panel inferior derecho), haz clic en New Folder y crea la estructura base descrita anteriormente (data, data/raw, data/processed, scripts, figuras).

1.3 Estructuras de Datos

En R, todo es un objeto. Para crear estos elementos en la memoria, utilizamos el operador de asignación <- (evite el uso de = para asignaciones, ya que puede confundirse con igualdad lógica).

1.3.1 Estructuras Homogéneas (Mismo tipo de dato)

Contienen elementos de una sola clase (números, texto o lógicos):

  • Scalar: Un único valor individual.
  • Vector: Una colección indexada de valores de una dimensión. Se crean con la función combinar c().
  • Matriz: Una estructura bidimensional donde todos los datos son del mismo tipo.
  • Array: Una generalización de la matriz de más de 2 dimensiones.
  • Scalar
  • Vector
  • Matriz
  • Array
s1  <-  2
s2  <-  "hola a todos"
s3  <-  3==4
v1  <-  c(2,4,6,8,10)
v2  <-  c("a", "b", "c", "hola", "buenos días")
v3  <-  v1>5
m1  <-  matrix(c(1, 2, 3, 4) , 2, 2 )
m2  <-  matrix(c("a", "b", "c", "d") , 2, 2 )
m3  <-  m1>=2
a1  <-  array(1:8, c(2, 2, 2))

1.3.2 Estructuras Heterogéneas (Múltiples tipos de datos)

Permiten combinar diferentes naturalezas de información:

  • Data Frames: Es el formato estándar de las bases de datos (tabular). Cada columna es una variable (puede ser de distinto tipo) y cada fila es una observación.
  • Listas: El objeto más flexible; puede contener vectores, matrices, modelos y hasta otras listas en un solo contenedor.
  • Dataframe
  • Lista
nombre  <- c("Maria", "Jose", "Ana")
edad    <- c(19, 30, 23)
df1     <- data.frame(nombre, edad)
df1
s1 <- 1; v1 <- c(1,2)
l1 <- list(s1, v1, df1)
l1

1.4 Fundamentos Metodológicos y Estadísticos de los Datos

Antes de escribir código para importar un archivo, es indispensable comprender la naturaleza metodológica y estadística del conjunto de datos con el que trabajaremos.

1.4.1 Nomenclatura Estándar en Análisis de Datos

En el ámbito del análisis de datos y la estadística, interactuamos con diferentes estructuras de información Wickham et al. (2023):

  • Datos Estructurados: Información organizada en tablas formales de filas y columnas (dataframes), donde cada fila representa una observación y cada columna una variable.
  • Datos Semiestructurados: No tienen una estructura tabular rígida pero contienen marcadores o etiquetas organizativas (ej. archivos JSON o XML).
  • Datos No Estructurados: Información sin un formato predefinido (ej. textos libres, audios, imágenes).
  • Dataset (Conjunto de Datos): Colección estructurada de datos.
  • Observación (o Caso): La unidad mínima sobre la cual se recopilan los datos (fila).
  • Variable: Una característica cuantitativa o cualitativa medida sobre las observaciones (columna).

1.4.2 Fuentes de Información y su Naturaleza

La procedencia y el diseño de la recolección de los datos determinan el tipo de conclusiones estadísticas válidas que podemos extraer Groves et al. (2009):

  • Censos: Recolección de información sobre la totalidad de los elementos de una población de interés. Proporcionan parámetros poblacionales exactos pero conllevan altos costos y tiempos de ejecución.
  • Encuestas por Muestreo: Recolección de datos sobre un subconjunto representativo (muestra) extraído probabilísticamente de la población. Permiten realizar inferencia estadística sobre la población general con un margen de error controlable Groves et al. (2009).
  • Registros Administrativos: Datos recopilados de manera continua con propósitos de control institucional u operativo (ej. registros tributarios, aduaneros o ingresos institucionales). Tienen la ventaja de ser económicos y continuos, pero no están diseñados originalmente con fines estadísticos, lo que suele requerir un trabajo de depuración previo.

Adicionalmente, según el nivel de control en la obtención de datos, distinguimos entre:

Dimensión Datos de Estudios Observacionales Datos Transaccionales / Operativos
Origen / Propósito Diseñados por un investigador para responder una hipótesis o pregunta concreta. Generados automáticamente por la operativa continua de un sistema o plataforma.
Control sobre las variables Sin intervención directa en los sujetos, pero con control explícito en el instrumento de medición. Ninguno. Registra únicamente los eventos conforme suceden en el sistema.
Volumen y Frecuencia Muestras finitas o acotadas tomadas en momentos específicos. Flujo continuo de gran volumen, generado en tiempo real o por lotes.
Calidad y Limpieza Alta consistencia lógica previa, pues se diseñan variables y escalas predeterminadas. Requiere procesamiento previo, ya que suele contener datos duplicados, nulos o imprecisiones.
Capacidad de Inferencia Diseñados estadísticamente para inferir hacia una población o identificar asociaciones controlando sesgos. Útiles para describir comportamientos históricos y patrones; la inferencia estadística requiere evaluación cuidadosa de sesgos de selección.

1.4.3 Población Objetivo y Unidad de Análisis

Antes de realizar la ingesta de un dataset, todo analista debe responder con precisión dos preguntas fundamentales:

  1. ¿Cuál es la Población Objetivo (Target Population)?: Es el conjunto completo de elementos sobre los cuales se desean realizar generalizaciones o inferencias Groves et al. (2009).
  2. ¿Cuál es la Unidad de Análisis?: Es el elemento básico sobre el cual se realiza la medición o la observación en el dataset (ej. una persona, un hogar, un evento, una institución).
ImportantFalacia Ecológica

Confundir la unidad de análisis puede llevarnos al sesgo de la falacia ecológica: cometer el error de deducir conclusiones sobre individuos a partir de datos agregados de un grupo (por ejemplo, asumir que porque un departamento del país tiene un promedio de ingresos alto, cada habitante seleccionado al azar de ese departamento posee necesariamente ingresos altos).

1.5 Ingesta de Datos Estructurados

Una vez configurado nuestro proyecto y definida la naturaleza metodológica de nuestros datos, procedemos a cargarlos en la memoria de R para su análisis.

1.5.1 Archivos Planos (CSV, TXT)

Los archivos de texto plano delimitados (como CSV o TXT) son los formatos más universales para el intercambio de datos estructurados. Estudiaremos dos enfoques de lectura: las funciones nativas de Base R y las funciones optimizadas del paquete readr (parte de tidyverse) Boehmke (2016).

  • Enfoque Base R
  • Enfoque readr (Recomendado)

Las funciones tradicionales como read.csv() no requieren cargar paquetes externos, pero presentan limitaciones de rendimiento en archivos grandes y pueden aplicar conversiones automáticas no deseadas.

# Lectura usando Base R
# stringsAsFactors = FALSE evita que columnas de texto se fuercen a factores categóricos
datos_base <- read.csv("data/raw/datos_bolivia.csv", stringsAsFactors = FALSE)

# Inspeccionar estructura básica
str(datos_base)

El paquete readr está diseñado para el análisis moderno: es significativamente más rápido que Base R, lee los archivos directamente como tibbles (estructuras legibles de dataframes) y no altera los nombres de las columnas Boehmke (2016).

library(readr)

# Lectura moderna con readr
datos_readr <- read_csv("data/raw/datos_bolivia.csv")

# Ver especificación de columnas detectada
spec(datos_readr)

Para garantizar la correcta lectura de archivos con inconsistencias o estructuras complejas, se deben dominar los siguientes argumentos:

  • col_names / header: Define si la primera fila contiene los nombres de las variables (TRUE o FALSE).
  • delim / sep: Especifica el carácter delimitador de campos (ej. ,, ;, \t para tabuladores).
  • na: Define explícitamente qué valores de texto deben interpretarse en R como un valor faltante real (NA). En bases de datos reales, es común ver valores perdidos codificados como "999", "N/A" o simplemente guiones "-".
  • skip: Permite saltar un número determinado de líneas iniciales (útil cuando los archivos contienen cabeceras informativas antes de la tabla real de datos).
# Ejemplo de ingesta controlada de un archivo CSV con inconsistencias
datos_limpios <- read_csv(
  file = "data/raw/datos_bolivia.csv",
  col_names = TRUE,
  na = c("999", "N/A", "-"),
  skip = 3,           # Omitir las primeras 3 líneas de metadatos o comentarios
  n_max = 1000        # Cargar solo las primeras 1000 observaciones para prueba rápida
)
NoteActividad de Paso: Definición Preventiva de Tipos de Datos (3 minutos)

Al importar datos, identificadores categóricos como la Cédula de Identidad (CI) o códigos de zona pueden ser erróneamente interpretados por R como variables numéricas continuas sobre las cuales no tiene sentido calcular promedios.

Para prevenir esto, podemos forzar el tipo de dato correcto durante el proceso de lectura:

  • Enfoque Base R
  • Enfoque readr
# Forzar columna 1 como numérico y columnas 2 y 3 como carácter
datos_preventivos <- read.csv(
  "data/raw/datos_bolivia.csv",
  colClasses = c("numeric", "character", "character")
)
library(readr)
# Definir tipos específicos de columnas
datos_preventivos <- read_csv(
  "data/raw/datos_bolivia.csv",
  col_types = cols(
    id_registro = col_character(),
    ci_nit = col_character(),
    monto_bs = col_double()
  )
)

1.5.2 Hojas de Cálculo (Microsoft Excel)

A diferencia de los archivos planos, los archivos de Microsoft Excel (.xls, .xlsx) son binarios y pueden albergar múltiples pestañas, estilos, celdas combinadas y fórmulas.

Antes de leer una hoja de Excel en R, se debe asegurar que la estructura sea tabular:

  1. Fila única de cabecera: Los nombres de las variables deben estar en la primera fila. Evitar cabeceras dobles o celdas combinadas.
  2. Una observación por fila: No intercalar filas de totales, resúmenes parciales o comentarios intermedios.
  3. Sin formatos de celda con significado analítico: Si una celda destacada en rojo tiene una connotación específica (ej. “pendiente”), esa información debe convertirse en una variable explícita en su propia columna (ej. estado = "pendiente") antes de la ingesta, ya que R no leerá colores de relleno como datos.

Para importar estas hojas de manera eficiente, utilizaremos el paquete readxl de la suite tidyverse Boehmke (2016).

  • Ingesta de Hoja Por Defecto
  • Ingesta de Pestaña Específica y Rangos
library(readxl)

# Lee la primera pestaña del libro de Excel de forma automática
datos_excel <- read_excel("data/raw/reporte_regional.xlsx")
library(readxl)

# Leer una pestaña específica por su nombre
datos_pestana <- read_excel(
  path = "data/raw/reporte_regional.xlsx",
  sheet = "lapaz"
)

# Leer un rango específico de celdas delimitado
datos_rango <- read_excel(
  path = "data/raw/reporte_regional.xlsx",
  range = "B5:F105"
)

1.6 Adquisición de Datos desde la Web: Scraping y APIs

La recolección moderna de datos requiere, en muchos casos, interactuar con fuentes públicas o plataformas en la web. Estudiaremos cómo automatizar este proceso mediante el consumo de APIs especializadas y la extracción de datos desde documentos HTML.

1.6.1 El Ciclo de Recopilación de Información (Los 5 Pasos de Iacus)

Para evitar sesgos y garantizar que la recolección automática de información desde la web sea un proceso riguroso (Iacus et al. 2015), se debe seguir una secuencia metodológica estructurada:

[1. Definición de Necesidad] ──> [2. Identificación de Fuentes] ──> [3. Teoría de Generación]
                                                                            │
[5. Toma de Decisión y Captura] <── [4. Evaluacion Técnica e Implicaciones] ┘
  1. Definición de la Necesidad de Información: Delimitar con precisión qué datos se requieren para responder a la pregunta de investigación o análisis.
  2. Identificación de Fuentes en la Web: Buscar portales digitales que contengan las variables requeridas para el estudio.
  3. Teoría del Proceso de Generación de Datos: Comprender quién genera el dato, con qué frecuencia se actualiza y qué posibles sesgos o limitaciones de cobertura presenta la fuente de origen.
  4. Evaluación Técnica e Implicaciones de Uso: Evaluar la viabilidad técnica de la extracción frente a las políticas de uso de la plataforma y las pautas establecidas en su archivo de configuración robots.txt (ej. https://www.ejemplo.com/robots.txt).
  5. Toma de Decisión e Inicio de la Recopilación: Diseñar el script de extracción automatizada garantizando la integridad, consistencia y almacenamiento de los datos capturados.
NoteActividad: Planificando la Captura (10 min)

Instrucción: En grupos de tres estudiantes, elijan un portal institucional, académico o de noticias locales.

  1. Definan una pregunta o necesidad de información que requiera recopilar datos de ese sitio.
  2. Identifiquen si los datos que obtendrán corresponden a un estudio observacional o a un registro transaccional/operativo.
  3. Mencionen dos posibles inconsistencias o ruidos que esperan encontrar en la data cruda.

1.6.2 Fundamentos de la Web: HTML y CSS

Para realizar la extracción de datos sin navegación manual (Mitchell 2015), debemos comprender el lenguaje básico con el que se estructuran las páginas web. El HTML (HyperText Markup Language) es un código basado en etiquetas que define la estructura del contenido.

HTML funciona bajo una estructura jerárquica delimitada por etiquetas (tags) y atributos. Por ejemplo:

<div class="seccion" id="region_lapaz">
  <span class="categoria">Artículos de Estudio</span>
  <span class="valor">750.00</span>
</div>

Para dar estilo a estos elementos, se utilizan hojas de estilo en cascada (CSS), que asignan clases (como .categoria o .valor) a las etiquetas. Estas clases actúan como selectores o identificadores que le permiten a nuestro código en R extraer de manera precisa la información de interés.

1.6.3 Web Scraping con rvest

En R, la librería estándar para interactuar con páginas web estáticas es rvest, perteneciente al universo tidyverse. Para identificar fácilmente el selector CSS de cualquier elemento de una página, se suele utilizar la extensión de navegador SelectorGadget.

  • Instalación y Carga
  • Funciones Clave
  • Ejemplo Práctico
# Instalación (se ejecuta una sola vez)
install.packages("rvest")

# Carga de librerías en la sesión actual
library(rvest)
library(dplyr)

La extracción con rvest se realiza combinando las siguientes funciones mediante el operador tubería (pipe %>%):

  • read_html(): Descarga y analiza la estructura del documento HTML.
  • html_nodes() / html_elements(): Selecciona los nodos que coinciden con el selector CSS indicado.
  • html_text() / html_text2(): Extrae el texto contenido en las etiquetas limpiando el código HTML.
  • html_table(): Convierte tablas HTML (<table>) directamente en data frames de R.

Sintaxis básica para extraer elementos de texto según su clase CSS:

library(rvest)
library(dplyr)

# 1. Leer la página web de origen
url_pagina <- "[https://ejemplo-institucional.org](https://ejemplo-institucional.org)"
web_html   <- read_html(url_pagina)

# 2. Capturar nodos específicos y extraer texto limpio
elementos_texto <- web_html %>%
  html_nodes(".categoria") %>%
  html_text()

1.6.4 Consumo de Interfaces de Programación de Aplicaciones (APIs)

Aunque el Web Scraping es una herramienta versátil, presenta una limitante: si la estructura o diseño estético de la página web cambia, el script puede fallar. Una alternativa más estable para la ingesta de datos son las APIs (Application Programming Interface).

Una API es un canal estructurado ofrecido por un servidor web para permitir la consulta y transferencia automática de datos en formatos estandarizados (como JSON o XML).

Dimensión Analítica Web Scraping Consumo de APIs Oficiales
Estabilidad Sensible a cambios de diseño estético del sitio. Alta; las estructuras y esquemas se mantienen estables.
Estructura Variable; requiere limpieza de sintaxis HTML. Estructurada; datos listos para formatear en JSON o XML.
Acceso Puede ser limitado por políticas del servidor. Regulado por parámetros, límites de peticiones o claves.

1.6.4.1 Ejemplo con Paquetes Especializados: Banco Mundial (wbstats)

En R, existen paquetes que simplifican el consumo de APIs públicas complejas evitando la redacción manual de peticiones HTTP. Un ejemplo es wbstats, que da acceso directo a los indicadores del Banco Mundial.

# Instalar y cargar la librería especializada
install.packages("wbstats")
library(wbstats)

# Buscar indicadores relacionados con desempleo o empleo
busqueda_indicador <- wb_search("unemployment")

# Descargar datos del indicador seleccionado para Bolivia desde el año 2000
datos_bolivia <- wb_data(
  country = "BO", 
  indicator = "SL.UEM.TOTL.ZS", 
  start_date = 2000, 
  end_date = 2025
)

# Visualizar las primeras observaciones del dataset
head(datos_bolivia)
